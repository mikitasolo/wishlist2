# UI kit & design system

AGENTS.md links here for the shared design rules: sizes, type, copy, components, colour and focus.

## Sizing, type & icons

- **One control size scale**, nothing hand-rolled; a control matches adjacent fields and a row shares one height. `sm` 36px (`h-9 text-sm`, 16px icons): toolbars, filters, page-header actions, list-row and compact-card actions. `md` 40px (`h-10 text-sm`, 16px icons): card action rows, field-less dialogs (`ConfirmDialog`, crop), header round buttons. `lg` 44px (`h-11 text-body`, 18px icons, default): form fields and buttons, a page's primary CTA. `xl` 48px: landing only. Labelled button = `Button` (`variant`, `size`, `shape="pill"` for page chrome and all page-header actions, `icon` drawn at its size); `type="button"` by default (as `IconButton`), so submits say `type="submit"`. Button-looking link: `buttonClassName` (`components/buttonStyles.ts`). Icon-only = `IconButton` with required `label`: 32px `xs` (default) for inline close/clear, else square at row height, always 18px icon (`iconButtonClassName` for links). Item card primary uses `md` `buttonClassName` (`success` / `success-soft` for Reserve and gift given). Only `Button` has primary glow/hover; one shared disabled look. `Select`: `sm` (toolbars) and `lg` (default), no `md`; on a phone toolbar give it a short `valueLabel` (Sort, Prices), menu keeps full labels. Text fields: `Input`, `Textarea`, `SearchField` (`lg`, `sm` in toolbars, `shape="pill"` in chrome e.g. header search). Below `sm` every text field types at 16px (`text-base`, then `sm:` its scale size): iOS browsers, Chrome included, zoom the page in on focusing a smaller one, so never set a field's text under 16px on a phone, and never block zoom (`maximum-scale`) instead (WIS-352). Picker triggers are buttons and keep the scale. Field-like popup triggers (`Select`, `MultiSelectDropdown`): `pickerTriggerClassName` with `leading` / `trailing` inside the border (prefix, status, clear), no hand-built wrapper, focus via `field-focus`. Wrap in `Field` (label, `helper`, `error`): control gets its id, `aria-describedby` helper+error, `aria-invalid` on error. `Field` reaches every inner `Input`/`Textarea`, so a popup's own search inside one (item form currency picker) is a plain `<input>` with `inputClassName('sm')`; a `SearchField` outside a `Field` needs `aria-label`. Labels/helpers beside non-`Field` controls (`Select`, `ImageUpload`): `FIELD_LABEL` / `FIELD_HELPER` (`components/fieldStyles.ts`); field-like trigger: `inputClassName()`.
- **One type scale; sentence case.** `@theme` (`app/globals.css`) adds `text-body` 15px (prose, empty-state body, compact card title, `lg` control label), `text-meta` 13px (meta line), `text-badge` 11px semibold (badges, pills, small uppercase labels), `text-title` 17px (grid card title, wordmark), rem with own line heights. Else Tailwind: page h1 `text-3xl font-semibold tracking-tight` (`sm:text-4xl` on a list, dashboard greeting, profile); section h2 and dialog title `text-xl`; panel and `ConfirmDialog` title `text-lg`; sub-section `text-base`; UI `text-sm`; helper `text-xs`. Headings semibold; bold only for stat numbers. No `text-[Npx]` (`test/unit/typeScale.test.ts` scans `app`, `components`, `lib`); add a token instead. Sentence case ("Save changes", "Delete item", "Discard changes?"), proper names aside. Only pending labels end in "…" ("Saving…", "Making member…"), never "..."; action labels never do, even ones opening a confirmation ("Delete", "Remove", "Leave list", "Release") (WIS-317, WIS-310; `test/unit/placeholderCopy.test.ts`).
- **Icons come in four sizes** (`components/Icon.tsx`; `test/unit/iconSizes.test.ts`): 12px in badges/pills and beside `text-xs`; 16px in `sm`/`md` controls (`CONTROL_ICON_SIZE`) and beside `text-sm`; 18px in `lg` controls, every `IconButton`, menu rows, chips up to 48px (Needs you row, toast, dialog); 28px in large chips (empty state, sign-in card). Always `Icon`, never inline `<svg>` or a glyph: `<Button icon="plus">Add item</Button>` not "+ Add item"; arrows `arrow-right`, Back `chevron-left`.
- **A count agrees with its noun** ("1 item", "2 items"): `plural(n, 'item')` (`lib/utils/plural.ts`), or `pluralNoun` when the number is set apart (bold); never a hand plural or ternary. Irregular plurals go in its table or are passed in.

## Copy & vocabulary

- **One word per act (D1)** in every user-read string (buttons, `aria-label`s, toasts, dialogs, notifications, emails, metadata, landing). Member **reserves** / **releases**; sees "Reserved by you", or "Reserved" for someone else's; never Book, Unbook, Booked, claim. Gifter **marks it as given** → **Gift history**; never "gifted". Owner **marks it as received** → **Received** (undo "Mark as not received"); never Completed. Visibility: **Public · Friends · Invite only** (`visibilityMeta`, `lib/utils/visibility.ts`, labels + helpers); never "Only me" / "Private". Copy only: stored names (`booked`, `completed`, `private`), `/booked` and API fields unchanged. Owners never see "Reserved" as a status; no copy names a proposer or reserver.
- **Confirmations never say a reservation goes when it stays.** Leaving, removing someone, move-to-draft and list delete keep reservations; no copy says they remove/cancel/delete a booking. Leave/remove/delete copy lives in `lib/utils/confirmationCopy.ts`, with the gifter's own toasts after accepting an owner invite and after leaving, which add the API's count via `releasedGiftsNote`: accept → `cancelledReservations` (may exceed items freed), leave → `unbookedItemsCount`. Only the gifter's own copy says what of theirs is kept or carries a count (leaving member's from items on their page). Owner copy may speak generally ("if someone reserved it"), never whether or how many. A danger `ConfirmDialog` that deletes nothing passes its own `icon` (`logout` leaving, `user-minus` removing), not the trash can; titles sentence case.

## Shared components

- **Use the shared kit, never a bespoke copy**: `Select`, `Menu`, `ConfirmDialog`, `BaseModal`, `Skeleton`, and `Cover` for every list/item image (gradient placeholder if missing/broken). List page banner: full-width strip above the title (`WishlistCover`: 4:1 phone, 3:1 capped 176px from `sm`); no banner, no strip. Banners stay cropped 16:9 (card and share-card shape); the strip trims with `object-cover`.
  - **`EmptyState`** (icon, title, body, `actions`; tone `default` / `muted` / `error`): every empty page, list, grid, search, in a dashed frame; `framed={false}` for not found / unavailable. `LoadError` = `error` tone + Try again for failed reads.
  - **`Badge`** (`sm`/`md`; `neutral`, `info`, `success`, `warning`, `danger`, `glass` over covers): labels, counts, cover pills. Item status only via `<Badge status={statusMeta(…)} />`. `badgeClassName` for self-laid-out labels (`OccasionLabel`).
  - **`Panel`** (`rounded-2xl border bg-surface shadow-sm p-5 sm:p-6`, `text-lg` title, muted description; `as="form"`; `variant="list"`: bordered header over divided `PanelRow`s) and **`PanelSection`** (sub-section under a line): Settings, Welcome, a list's People/Settings tabs, currency prompt.
  - **`SegmentedControl`** (`sm` 32px, `md` 36px): one of a few choices (list visibility, privacy, item status, followers dialog lists). WAI-ARIA radio group: one Tab stop on the selection; arrows (wrapping), Home, End move+select; tests `getByRole('radio', { name })`. (Account menu theme is a `MenuRadioGroup`.) **Theme: Light · Dark · System, default System** (`lib/utils/theme.ts`: `parseThemeChoice`, `resolveTheme`), in localStorage (System = nothing stored); `useTheme()` → `theme` (choice), `resolvedTheme` (drawn); layout inline script resolves System from `prefers-color-scheme` pre-paint, `ThemeProvider` follows OS changes. Drawn-theme consumers (Turnstile) read `appliedTheme()` / `resolvedTheme`, never the choice.
  - **`Callout`** (`info`, `warning`, `danger`, status tokens): in-form/page notice; `danger` is `alert`, others `note`.
  - **`Spinner`**: the only spinner, for waits inside on-screen content (upload). Loading pages show a skeleton of their layout from `Skeleton` blocks (never raw `.skeleton`).
- **Skeletons follow layout; every dialog is a `BaseModal` with `useFocusTrap`.** Layout change → update its skeleton. All dialogs but `ConfirmDialog` are `BaseModal` (incl. `CreateWishlistModal`, `FollowListModal`, `ImageCropModal`): portalled to `<body>`, `size` `sm` 24rem / `md` 28rem / `lg` 32rem (default), pinned header (`text-xl` title, 32px close `IconButton` named by `closeLabel`), scrolling body, optional pinned right-aligned `footer` (Cancel, then primary). `headerContent` pins controls under the title (followers tabs); `onSubmit` makes the panel the `<form>` (footer `type="submit"` and Enter submit). Never hand-build the shell. `useFocusTrap` (`lib/hooks/useFocusTrap.ts`): open → focus Cancel, the create form's name (`autoFocus`), else close button unless content has `autoFocus`; Tab stays in the topmost dialog, incl. one stacked from inside another (crop over item/create form); close → focus back to opener. While busy (hook `busy`: `BaseModal` `isSubmitting`, which also blocks every exit, or `busy`, which doesn't, so a crop can be cancelled) focus holds on the panel, not `<body>`, then returns to the control if still focusable. Traps count only their own Tab stops, so portalled popups (`Select` menu on `<body>`) keep focus on their control. `Select` = WAI-ARIA select-only combobox (`getByRole('combobox', { name })`, not button): trigger is the one Tab stop and keeps focus while open; Enter/Space/arrow opens on the selection; arrows, Home, End, type-ahead move via `aria-activedescendant`; Enter/Space pick; Escape/Tab close; menu keys stop at the trigger (its Escape won't close the dialog). Invite username field (`InviteMemberForm`, `getByRole('combobox', { name: 'Search by username' })`): editable combobox, same model; focus stays in field, ↓/↑ move, Enter picks (none active: sends as typed), Escape/Tab close, Escape stops at the field. `GlobalSearch` (`getByRole('combobox', { name: 'Search people and wishlists' })`): same, but the first result is active on arrival (Enter opens it), with results closed the header's Escape folds search; opened empty it lists up to five people you follow. Invite suggestions mark who's on the list (Owner, Member, Invited via `listStatusByUsername`, `lib/utils/inviteSuggestions.ts`, from loaded owners/members/pending invites) as disabled options; a member's offers **Make co-owner instead**, opening the page's own Make owner confirmation + promotion invite (one path). New overlays use the hook; new portalled popups keep focus on their control.
- **A toast can carry one action** (`showToast(message, type, { action })`, `ToastAction`, `components/ToastProvider.tsx`): `{ label, onClick }` → button, `{ label, href }` → link, inside the `role="status"` toast, dismissing on use; such toasts last 8s (not 4s). Successful member reserve (`useReserveToast`, `lib/utils/reserveToast.ts`, WIS-260): "Reserved — it's in Reserved by you" + **View** → `/booked`; first time per browser (`localStorage` flag) "Reserved. @owner won't see it; others on the list see it's taken." (sole owner's public username, else "the owners"). Failed reserve toasts only its error; owners never get reservation toasts. The "Reserved by you" card badge links to `/booked` ("Reserved by you, open Reserved"); others' "Reserved" doesn't.
- **A menu of actions is the shared `Menu`** (`components/Menu.tsx`, WAI-ARIA menu button; trigger `getByRole('button', { name })`, items `menuitem`). Account menu (`AuthButton`) is one: custom `trigger` (avatar, chevron from `sm`, told if open), non-item `header` (avatar, username, owner-only email; outside `role="menu"` so keys skip it), link items (`href`; `external` = new tab), theme `MenuRadioGroup` (`menuitemradio`s in arrow order, stay open on pick). Rendered in place, not portalled. Enter, Space (on keyup, else Firefox clicks the focused item) or ArrowDown open on first item, ArrowUp on last; pointer opens with the menu focused. Arrows (wrapping), Home, End, typed letter move; Escape, Tab, outside click, focus leaving close (Escape/Tab refocus trigger). Picking refocuses the trigger before the action runs (so its dialog returns focus there). Focus never strands on `<body>`: item removed under it (poll) → menu; menu closing with focus lost → trigger. `disabled` item is `aria-disabled`: in arrow order, picking does nothing.

## Layout & spacing

- **One spacing rhythm.** Page `<main>`: `mx-auto px-4 sm:px-6 lg:px-8 py-8 sm:py-10`, `max-w-7xl` for grids, `max-w-2xl` single column (Settings, Welcome, Booked, Activity); content `mt-8` under title/subtitle (list page cover strip, header, description, chips, toolbar keep `mb-6` / `mb-6 sm:mb-8`). Card grids `gap-5` (`grid-cols-1 sm:grid-cols-2 lg:grid-cols-3 xl:grid-cols-4`), `SkeletonGrid` too; exception: list item grid, 2 columns on phone, `gap-4` (`ITEM_GRID_CLASSES`, `components/Skeleton.tsx`, shared with skeleton). **A section of lists is a `WishlistList`** (`components/WishlistList.tsx`: dashboard Your wishlists / Shared with you, `/wishlists/mine`, `/wishlists/shared`): cards from `sm`; below `sm` compact `WishlistRow`s (~72px: 56px `Cover`, name, meta from `rowMeta` (`lib/utils/listRows.ts`, shared with card owner line), occasion, own list's visibility icon or shared list's `ReservedByYouChip`; extra line if occasion doesn't fit) in one divided `rounded-2xl` panel (WIS-254). Both in first paint via CSS (`sm:hidden` / `max-sm:hidden`), then `useMediaQuery` drops the hidden one; skeleton `WishlistListSkeleton`, row for row. Archived lists fold into `ArchivedLists` at the end of dashboard and Your wishlists: "Archived (n)" disclosure (`aria-expanded`, inside its `h2`), closed at every width unless it's all the page has. Profile grid stays cards. Sections `space-y-12`; stacked `Panel`s `space-y-6` / `mb-6`. Fields `space-y-4`; label `mb-1.5`, helper `mt-1.5` (`FIELD_LABEL` / `FIELD_HELPER`), helper between label and control `mb-1.5`. Button groups (header actions, dialog footer, row actions) `gap-3`; a card's action row `gap-2`. Skeletons mirror pages box for box at real line heights (`WishlistCardSkeleton`, `ItemCardSkeleton`, `DashboardSkeleton`: greeting row, section heading over `WishlistListSkeleton`, no box for Needs you / Coming up); `e2e/layout-stability.authed.spec.ts` checks dashboard, Mine, Shared don't shift.

## Colour, popovers & focus

- **Hover and delete look the same everywhere.** Only link cards (`WishlistCard`) lift on hover (`hover:shadow-lg`); item cards and landing features don't. Red = `danger` tokens only, never `red-*` / `hover:bg-red-50`: red button tint `bg-danger/10` (hover `/16`), red chip/toast icon `TONE_CLASSES.danger.tint`, both dark-aware. Starting a delete: soft red (`Button` `danger`, or `danger-ghost` among quiet actions, incl. edit dialogs' Delete item); solid `destructive` only confirms (`ConfirmDialog`). Clear/close buttons ≥32×32 (`IconButton` `xs`): search clear, header search close, toast dismiss.
- **Accent text is `text-accent`, no dark override.** `--accent` already lightens in dark (`#a3a1ff`); never `dark:text-primary-300/400` or raw `text-primary-600/700` for links/accent. Soft indigo tint `bg-primary-500/12` (hover `/18`): `soft` button, indigo chips.
- **Every popover has one look** (`components/popoverStyles.ts`): `POPOVER_SURFACE` `rounded-xl border bg-surface p-1.5 shadow-lg`; inset rows `rounded-lg px-3 text-sm font-medium`, `bg-muted` on pointer hover, `bg-row-active` on the keyboard row (focused `Menu` item, active `Select` option, which the pointer also moves): indigo tint token in `globals.css` (primary-600 16% light, 1.24:1; primary-400 28% dark, 1.55:1) since `bg-muted` (~1.1:1) is too faint. Row icons 18px (`MENU_ICON_SIZE`); option rows 36px (`POPOVER_OPTION_ROW`: `Select`, checkbox lists, search/invite results), action rows 40px (`POPOVER_ACTION_ROW`: `Menu`). New popups build on these. Pick-several filter: `MultiSelectDropdown` (Items' list filter), checkboxes under an All row. Checkbox colour: `accent-primary-600` (`text-*` / `border-*` don't affect native ones).
- **Base CSS lives in `@layer base`, so utilities always win.** Tailwind v4 utilities sit in `@layer utilities` and unlayered CSS beats all layers (WIS-233), so new element-wide defaults (`*`, tag, attribute) go inside that block, never after. **Focus:** every control shows the base 2px `--ring` outline (follows radius); only remove it if something else shows focus, and via `outline-hidden`, not `outline-none` (forced-colors draws only the former). Text fields and field-like triggers (`Select`, filter dropdowns): `outline-hidden field-focus` (`@utility` in `globals.css`: ring-colour border + 2px `ring-ring/20` halo, on the field or the wrapper drawing a borderless input's border — prefix, icon, clear — shown only while the inner input is focused). Active `Menu` item / `Select` option: `bg-row-active` alone (account menu too); `Menu` radio group options (segments in a track) keep the outline. `e2e/focus-styles.*.spec.ts` checks in a browser (jsdom ignores layers).
- **Status colours only via status tokens and `statusMeta`.** `lib/utils/itemStatus.ts` is the one map: `statusMeta(status, role, { bookedByViewer })` → label, tone, icon, classes; `LIST_CHIP_LABELS` (`lib/utils/listChips.ts`) derives from it. Every status surface reads it (item badges/borders, list chips, `/items` stat cards/badges, status filter); rename there only. Tone classes (badge, text, card border, tint, notice): `TONE_CLASSES` (`lib/utils/statusTones.ts`), also for other meaningful colour (notices, toasts, `ConfirmDialog`, Booked "needs confirmation" cards). Tones are `@theme` tokens with dark values in `app/globals.css`: `bg-<tone>-fill` (+ `-fill-hover`) with white text, `text-<tone>`, tint `bg-<tone>/10`–`/15`, for `info`, `success`, `warning`, `danger`, each ≥4.5:1 in both themes. **Done** (Received) is neutral (`bg-foreground text-background` + ✓), never green ("Reserved by you"). No raw palette classes (`emerald-*`, `amber-*`, `green-*`, `blue-*`, `yellow-*`, `teal-*`, `red-*`, `orange-*`, `rose-*`); `test/unit/itemStatus.test.ts` scans `app`, `components`, `lib` (Avatar's gradients excepted). Errors/destructive = `danger`; "Most wanted" star = `fill-star text-star-edge` (`--color-star`, `--color-star-edge`), not a status. The map gives owners a booked item's `available` meta: no booked label, tone or border for owners.
